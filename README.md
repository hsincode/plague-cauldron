# Plague Cauldron

An unofficial fan re-creation of the gameplay shown in a 58-second mobile game ad, extended into a short complete
game: a plague doctor scoops bubbles out of a river, grinds them into potion, bathes the sick villagers in a cauldron
and spends their coins on helpers until the whole village is cured (about five minutes).

Everything in it is original and procedural: the models, textures, icons, sounds and music are generated by the code
in this repository. It contains no assets of the original game, and the ad itself is not part of the repository. It
is not affiliated with the original game or its publisher.

## Run, test, build

Requirements: [Bun](https://bun.sh) and a browser with WebGL2. The capture tools also need a Chromium.

```sh
bun install
bun run dev         # http://localhost:5174 (the game) and /gallery.html (models in isolation), hot reload
bun run typecheck
bun test            # headless simulation tests, about 2 minutes
bun run build       # dist/ plus dist/THIRD-PARTY-NOTICES.txt
bun run preview     # serves dist/ on http://localhost:5175
bun run deploy      # build, then publish dist/ to the Vercel project (needs a logged-in Vercel CLI)
```

CI (`.github/workflows/ci.yml`) runs the type check, the tests and the build on every push and pull request. On
`main` it then publishes that build to https://plague-cauldron.vercel.app, once the repository secret `VERCEL_TOKEN`
exists.

## Controls

| Input | Action |
|---|---|
| Drag (touch or mouse) | Move: a floating joystick appears where the drag starts |
| WASD / arrow keys | Move |
| Enter / Space | Start; play again from the win screen |
| M | Sound on / off |
| F | Fill the window instead of the 9:16 frame |
| R | Restart after winning |

Everything else happens by walking up to things. A window too short for the 9:16 frame (a phone held sideways) is
filled automatically.

## Development URL parameters

| Parameter | Effect |
|---|---|
| `?nostart=1` | Skip the title screen |
| `?autoplay=1` | The bot plays |
| `?ff=<seconds>` | Fast-forward that many simulated seconds with the bot before the first frame |
| `?speed=<multiplier>` | Simulation speed |
| `?seed=<n>` | Random seed of the simulation (default 1) |
| `?unlock=<ids>` or `?unlock=all` | Start with these unlocks (ids are in `UNLOCKS`, `src/config.ts`) |
| `?gold=<n>`, `?potion=<n>`, `?flasks=<n>` | Start with gold, potion in the cauldron, flasks carried |
| `?cam=x,z[,zoom]` | Hold the camera on a ground point |
| `?views=a,b` | Only these view modules (`stations`, `actors`, `river`, `drill`, `coins`) |
| `?quality=low`, `high` or `auto` | Pin the render quality, or let the resolution scale adapt it. The default is `auto`, except in an automated browser, which gets `high` so that captures are repeatable |
| `?wide=1` | Start in the wide layout |
| `?mute=1` | Start muted |
| `?debug=1` | Primitive debug view instead of the models |
| `?dev=1` | P pauses |

`window.__game` exposes the same to the console and to scripts: `state`, `cheat.gold / unlock / potion / flasks / tp /
drive`, `skip(seconds, useBot)`, `lookAt(x, z, zoom)` / `follow()`, `pause()`, `frames`, `stage`, `ctx`, `director`,
`audio`.

## Source tree

| Path | Contents |
|---|---|
| `docs/SPEC.md` | The design, measured from the ad (`[SEEN t]`) and extended beyond it (`[EXTENDED]`) |
| `src/config.ts` | Every tunable number, the world layout, the palette, the unlocks |
| `src/sim/` | The simulation: deterministic, headless, plain-data state (`types.ts`), events (`events.ts`), the bot (`bot.ts`) |
| `src/world/`, `src/core/` | Geometry shared by simulation and view; math and the seeded random generator |
| `src/view/` | three.js: stage and post-processing, environment, models, the five views that bind models to the state, camera |
| `src/ui/` | HUD, ground decals, icon bubbles, the guide arrow, input |
| `src/audio/` | Synthesised sound effects, ambient beds and music (WebAudio) |
| `src/main.ts`, `src/gallery.ts` | The game shell and loop; the model gallery |
| `test/` | Simulation tests (`bun test`) |
| `tools/` | Capture tools, the build's licence notices, the preview server |

## Capture tools

```sh
bun tools/shot.ts "<url>" out.png [width=608] [height=1080] [waitMs=1500] ["js to evaluate"]
bun tools/seq.ts "<url>" outDir [width] [height] -- w=500 js="__game.cheat.gold(500)" s=name fps=2000 key=KeyD:800
```

`shot.ts` takes one screenshot; `seq.ts` runs a list of steps in one page (wait, evaluate, screenshot, measure the
frame rate, hold a key). Both launch `/usr/sbin/chromium`; set `CHROMIUM_PATH` to use another one.
